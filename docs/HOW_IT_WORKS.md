# How Fieldcard Works

Fieldcard is architected on a fundamental design rule:

> **The LLM writes the poetry; code does the safety math.**

The screen is the doorway, not the destination. Fieldcard takes a location, a time budget, and an outdoor activity, and turns them into a physical A5 paper field guide.

```
       [User Input: Lat/Lon, Minutes, Activity]
                         │
        ┌────────────────┼────────────────┐
        │                                 │
 [Deterministic Math]              [Open Data APIs]
  * NOAA Solar Equations            * OpenStreetMap (Overpass)
  * Haversine & Compass Bearings    * iNaturalist Monthly Observations
  * Turnaround & Reach Safety       * Local Disk Cache (~/.cache/fieldcard)
        │                                 │
        └────────────────┬────────────────┘
                         │
               [Open-Weight LLM]
                * Ollama (Llama 3.2 3B / Gemma 2 2B)
                * Grounds mission in real terrain
                * Generates 9 tactile observation prompts
                * Strict JSON schema & banned-word filter
                         │
               [A5 Print Rendering]
                * Single-page print CSS guarantee
                * Radial SVG compass map
                * Physical paper fieldcard.html / PDF
```

---

## 1. Safety Math & Deterministic Code
Outdoors, errors in daylight calculations or trail distances have real consequences. Models frequently hallucinate times and distances, so Fieldcard leaves zero math to the LLM:

* **Daylight & Sunset**: Uses NOAA solar zenith equations in pure Python standard library to compute exact sunrise, solar noon, sunset, and dusk for the given coordinates, date, and timezone. If a walk extends past sunset, a prominent daylight warning is calculated with the latest safe start time.
* **Trail Reach**: Computes straight-line reach using the Haversine formula, adjusted by an empirical 1.3× winding trail factor and walking/running speeds.
* **Turnaround Point**: Strictly half of the total time budget. If you have 90 minutes, your turnaround is exactly at minute 45.

---

## 2. Open Data Without Accounts or Keys
Fieldcard relies on public open-source knowledge bases:
* **OpenStreetMap (Overpass API)**: Queries nodes and ways for parks, water, peaks, nature reserves, and viewpoints within your calculated reach. Results are cached locally by coordinate hash. If network is down, Fieldcard falls back to dead-reckoning sun rules.
* **iNaturalist**: Queries research-grade observations within 6 km for the current calendar month. Injects real local flora and fauna ("Seen nearby this month") so you know what is currently active in your ecosystem.

---

## 3. Open-Weight Models via Ollama
The title, mission, and sensory prompts are generated by a local open-weight model running on localhost via Ollama (`llama3.2:3b` by default, or Google `gemma2:2b` / `qwen2.5:3b`):
* **Untrusted Output Pipeline**: All LLM text is length-clipped, JSON validated, sanitized of banned marketing clichés ("embrace", "tapestry", "unplug"), and HTML-escaped.
* **Offline Fallback**: If Ollama is not running, Fieldcard instantly falls back to its curated seasonal sensory prompt bank.

---

## 4. Single-Page A5 Print Guarantee
Fieldcard uses calibrated print CSS (`@page { size: A5 portrait; margin: 6mm 7mm; }`) and SVG rendering to ensure the card fits on exactly one physical A5 sheet of paper under all configurations—whether you have 0, 3, or 5 places nearby.
